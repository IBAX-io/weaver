# Weaver 加密算法适配与安全修复说明

适用分支：`upgrade/latest-deps`
相关提交：`f8827a2`（支持 SM2/SM3）、`ff92c2b`、`f76c097`、`e5ad77b`（审计修复）、`d6fcfb7`（退出清除令牌）

## 一、网络、链与算法的关系

- Weaver 里配置的每个「网络」（主网、测试网、本地节点等）就是一条链。一个网络下可以列多个节点，客户端连接其中一个。
- 加密算法是按链定的：go-ibax 的算法写在节点配置里，同一条链的所有节点必须一致，否则彼此无法验证签名。
- **不同的链可以用不同的算法**，例如一条用 secp256k1 + Keccak-256，另一条用 SM2 + SM3。
- 客户端连接网络时通过 `/api/v2/getuid` 读取这条链的算法（`cryptoer`、`hasher`），之后的地址计算和签名都按它来。
- 同一把私钥在不同算法下地址不同。钱包里预先算好了全部 12 种算法组合下的地址，切换网络时直接显示对应地址，不需要密码，也不会退出登录。

支持的算法（与 go-ibax 一致）：

| 类别 | 支持 |
| ---- | ---- |
| 签名 | ECC_Secp256k1、ECC_P256、SM2 |
| 哈希 | KECCAK256、SHA256、SHA3_256、SM3 |

不报告算法的老节点，按 ECC_P256 + SHA256 处理。只报告了其中一个名字的节点，视为算法未知，不签名。

## 二、修复了一个可能泄露私钥的签名问题（最重要）

**问题**：同一个私钥对同一段内容签名时，在 secp256k1 和 P-256 下会用到同一个随机数。恶意节点只要先报一种算法、再报另一种，拿到两次登录签名就能算出用户私钥。实测 50 次全部成功。

**修复**：每次签名混入新的随机数和曲线名（RFC 6979 第 3.6 节的做法），SM2 同样处理，并对求逆做了盲化。

**验证**：用 go-ibax 交叉验证，36 种组合生成的公钥、账户 ID、登录签名和交易签名，节点全部接受。

**注意**：签名每次都不一样是正常的，不再是固定值。

## 三、同一条链修改算法配置后的处理

这里说的是**同一条链**把自己的算法配置改了（所有节点一起改）。不同的链本来就可以用不同算法，切换网络不受影响。

- 同一条链改了算法之后，用户原来的登录会话、地址和签名都还是旧算法的，已经不能用。
- 客户端会在三个时机核对链上算法：恢复登录时、登录时、发交易时（节点拒签时）。发现变了，就自动退出，并在这条网络的登录页说明原因。
- 重新连接后，账户按新算法列出。旧版本保存的账户，点「在此网络启用账户」并输入密码一次就能用。
- 少数私钥（约四十亿分之一）超出了 SM2 的可用范围。这种账户在 SM2 网络上没有地址，启用时会明确提示，在其他网络上照常使用。

**需要链上决定**：同一条链改算法后，账户地址会变，旧地址上的资产如何处理。客户端目前只负责切换到新地址。

## 四、退出登录会清除令牌

- 以前退出后，登录令牌还留在本地存储里。Weaver 登录时申请的有效期是 90 天，节点会按这个有效期签发。
- go-ibax 没有作废令牌的接口（只有 `/login` 和 `/auth/status`，令牌是无状态的 JWT），所以由客户端在退出时直接删除。
- 老版本已经留在用户电脑上的令牌，下次启动时也会被清除。

## 五、UTXO 转账记录与区块浏览器

- 节点没有 UTXO 转账的列表，所以先从区块浏览器找出有哪些转账，再逐条向节点核实：发送方、接收方、金额都以节点为准。
- 查询前会先征求用户同意，因为要把账户地址发给区块浏览器。同意按「网络 + 浏览器地址」记录，换了浏览器地址会重新询问。
- 区块浏览器地址只接受 https。
- 浏览器一次读不全的区块会明确提示，不会悄悄漏掉。

配置方式：在 `public/settings.json` 的网络里加 `explorer` 字段，格式见 `public/settings.json.dist`；也可以在「添加网络」页面填写。旧的 `settings.json` 不会被自动替换，需要手动补上，或者删除后让它重新生成。

## 六、升级后用户会遇到的情况

1. 用旧版本登录过的用户需要重新登录一次（旧会话没有算法信息，会被丢弃）。
2. 区块浏览器的查询同意需要重新确认一次。
3. 在新算法的网络上，旧版本保存的账户会出现在「尚未在此网络启用的账户」里，点「在此网络启用账户」并输入密码一次即可。

## 七、开发须知

- 包管理只用 yarn。Node 版本要求见 `package.json` 的 `engines` 字段（22.22.2 以上的 22、24.15.0 以上的 24，或 26 及以上）。
- 读取登录会话请用 `signedInSession(state)`（`src/app/modules/auth/selectors.ts`），不要直接写 `state.auth.session.xxx`：退出后会话为空，直接读会抛错。有测试专门检查这一点。
- 名字以 `ForTest` 结尾的导出只能在测试里用，同样有测试检查。
- 算法交叉验证的向量由 `scripts/go-ibax-vectors/main.go` 生成，用法写在文件开头。
